# ADR-0031: Optional dedicated SDXL inpainting model for rooms

Status: Implemented with offline protocol tests; image quality unverified until an
owner GPU trial. Extends ADR-0025 (which planned this comparison) and ADR-0029.

## Context

Room artwork is masked editing. Since ADR-0025 it has used the SDXL **base** checkpoint
with `VAEEncodeForInpaint` at denoise 1.0. A base model was never trained for inpainting:
it does not receive the mask or the surrounding image as inputs. Its only view of the
context is through the latent noise mask, which re-imposes the original pixels outside
the mask at each sampling step. Owner trials found invented partitions, wrong furniture
scale and rooms that do not continue their surroundings. Some of this is likely a
model limitation that prompt and ControlNet changes (ADR-0028, ADR-0029) cannot fix.

SD-XL Inpainting 0.1 (`diffusers/stable-diffusion-xl-1.0-inpainting-0.1`, openrail++)
is SDXL base fine-tuned for inpainting. Its UNet has 9 input channels: the usual 4 latent
channels plus 4 for the encoded masked image and 1 for the mask. ComfyUI detects this
diffusers-format UNet (`SDXL_diffusers_inpaint` in `comfy/model_detection.py`), loads it
with the core `UNETLoader` node from `models/diffusion_models`, and feeds the extra
channels through the core `InpaintModelConditioning` node. The fp16 UNet is 5.14 GB.

The owner prefers AI-generated walls to a deterministic overlay (the ADR-0030 prototype
is parked), so improving how well the model uses context is the priority.

## Decision

- **Inpainting graph v2.** All masked edits use `InpaintModelConditioning`
  (positive, negative, VAE, pixels, mask, `noise_mask: true`). Its positive and negative
  outputs and latent feed the KSampler. When ControlNet guidance is configured, the
  ControlNet outputs feed `InpaintModelConditioning`. Workflow versions:
  `comfy-sdxl-inpaint-v2`, and `comfy-sdxl-layout-v2` with ControlNet. Text-to-image
  (backgrounds) keeps the unchanged `comfy-sdxl-v1` graph.
- **Base checkpoint behavior.** Without a dedicated model, the latent holds the original
  encoded pixels with a noise mask, and the concat inputs are ignored by the 4-channel
  base UNet. At denoise 1.0 the initial masked latent is replaced by noise, so results are
  expected to be close to the previous `VAEEncodeForInpaint` graph. This is an
  expectation from ComfyUI's code, not a measured equivalence. The workflow hash changes.
- **Optional dedicated UNet.** New server-only setting `MWQ_IMAGE_COMFY_INPAINT_UNET`:
  a `.safetensors` filename (no directory) in ComfyUI's `models/diffusion_models`. When
  set, masked edits load it with `UNETLoader` (`weight_dtype: default`) as the sampler
  model. CLIP and VAE still come from the base checkpoint. Backgrounds always use the
  base checkpoint. Quill neither bundles nor downloads weights.
- **Readiness.** When configured, readiness requires `UNETLoader` and the filename in its
  `unet_name` list; a missing file fails readiness instead of silently falling back. The
  readiness message reads "Ready · dedicated SDXL inpainting model for rooms" so the AI
  panel shows which path is active. No contract change: the message is existing text.
- **Provenance.** Masked-edit runs record `inpaintModel` (the filename, or null for the
  base checkpoint) and the new workflow version in `parameters.comfyui`. Existing records
  stay valid; generation-record validation does not depend on these fields.
- Sampler settings are unchanged: 20 Euler/normal steps, CFG 7, denoise 1.0, batch one.
  Quill's own compositing still protects every pixel outside the room mask exactly.

## Consequences

- Rooms can be generated by a model trained to fill a masked area consistently with its
  surroundings. Whether this reduces seams, invented partitions and scale errors must
  be measured on the owner's hardware; offline tests cannot show it.
- Memory: ComfyUI holds both the base checkpoint (for CLIP and VAE) and the 5.14 GB
  inpainting UNet. On the 8 GB reference GPU this relies on ComfyUI's model offloading,
  costing time; `--lowvram` may be needed. Not measured.
- **Untested combination:** ControlNet guidance with the dedicated UNet. ComfyUI's
  Control-LoRA builds its control network from the active model's configuration and
  weights, so this is plausible, but nothing has run it. If it fails, unset one of the
  two settings and record the failure.
- Fooocus-style inpaint patches, differential diffusion and soft masks need custom
  nodes or changes to Quill's binary-mask contract and are out of scope.

## Verification

Offline tests (`tests/test_comfyui.py`, `tests/test_comfy_editor.py`) cover the v2 graph
wiring with and without ControlNet, `UNETLoader` use only for masked edits with CLIP and
VAE kept on the base checkpoint, unchanged text-to-image graphs, readiness failure when
the configured UNet is missing, filename validation, environment loading, provenance and
the readiness message. Existing mask-orientation and outside-pixel preservation tests
are unchanged and pass.

Next: owner trial comparing the same rooms and seeds with base SDXL and the dedicated
UNet (with ControlNet off, then on), recording time and peak VRAM. Then add a FLUX.2
klein workflow as a second local option.
